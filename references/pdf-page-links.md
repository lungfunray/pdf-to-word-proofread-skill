# 原 PDF 页码链接

仅在制作或补充 Word 页码链接时读取。用户说“这一步先不用做”时，仅保存流程要求，不修改现有 Word 或源 PDF。

## 构造链接

1. 确定真实源 PDF 的绝对路径及目标页序 `N`（从 1 开始）。书内印刷页码是链接显示信息，不能直接当作 `N`。
2. 首选将本地文件 URI 与页定位片段合并，例如 `file:///C:/.../source.pdf#page=2`。用 `pathlib.Path(pdf_path).resolve().as_uri()` 编码中文、空格与特殊字符，不手工拼接未经转义的 Windows 路径。
3. 用原生 Word 超链接包装 `原PDF第N页 · 书内第M页`。OOXML 方式：在所属 document 或 footer 部件建立类型为 `hyperlink`、`TargetMode="External"` 的关系；`w:hyperlink` 通过该部件的 `r:id` 引用关系。
4. 超链接内所有文字 runs 明确设 `w:color=FF0000`，覆盖默认蓝色主题，并用红色下划线表示可点击。不能仅在文档正文写一个看似链接的路径。
5. 多页链接分别指向各页，不能全部指向首页。PDF 位于本机时，不擅自上传或发布来解决链接兼容性。

示例仅说明目标构造，不代表已经验证阅读器行为：

```python
from pathlib import Path

pdf_page_index = 2
target = Path(pdf_path).resolve().as_uri() + f"#page={pdf_page_index}"
```

## 验证与兼容性

`#page=N` 是常见 PDF 打开参数，但 Word、操作系统文件关联和阅读器可能不传递或不支持片段。因此必须区分三层证据：

- **结构已写入**：超链接关系、红色格式、目标文件及 PDF 页序正确。
- **PDF 可以打开**：点击后能打开该文件。
- **跳到对应页已验证**：在实际 Word 与阅读器组合中点击后，核实目标物理页与预期一致。

只有最后一层才可以声称“点击直接跳到对应页”。无法实际点击验证时，交付说明“链接已加入，跳页行为尚未验证”。用户明确跳过检查时同样如此。

阅读器忽略片段时，保留正确的源文件链接和可读页码，明确报告没有实现直接跳页。若用户仍要求直接跳页，调查其实际阅读器支持的方式，再选择可验证的方案；不要用宏、执行脚本的链接、修改系统文件关联或外部上传来静默替代普通超链接。

文件移动后本地绝对路径可能失效。源 PDF 与 Word 需要一起分发时，可改用同目录相对文件关系，仍需验证点击和页定位；不默认复制大文件、改变源文件位置或修改原 PDF。
